# dsh-weknora-memory 演进路线图

本文是这个项目的演进路线图：读侧是 `@rennimars/dsh-weknora-memory` 插件——把历史会话沉淀成"事实卡"，在对话开始时把相关记忆注入上下文；写侧是配套的每小时导入、每晚蒸馏与夜间裁决脚本。
当前发布版本 0.3.0。读侧"零依赖、静默失败、只读扫描"与写侧"永不进插件热路径""单写入者边界"（lib/config.js:114-118）在全部阶段都不动。
计划性质：可分批实现，每批独立验收——每个阶段都能单独交付、单独回滚，不必等前一阶段全部落地。
每阶段门禁：`npm test`（59 用例）全绿 + 重启后跑一次验证脚本 + 题库命中率不低于上一阶段 + 一轮真实对话确认注入块形态。
下面第 2–8 节是阶段 0–6 的正文；每条阶段都已拆成一条 Issue，欢迎在 Issue 区按阶段提方案、认领或反驳其中任何一条。

## 5. 阶段 3 · 自动裁决 <a id="阶段-3"></a>

**目标**：让"新证据改写旧信念"真正发生，而不是只记冲突日志。

**改动点**

1. distill.mjs:474/:537 的冲突记录保持原样（已有数据结构），但补字段：新卡文档 id、旧卡文档 id、主题标签、相似度、生效日期，写成结构化行（不再只是自然语言描述）。
2. dream.mjs 新增前置阶段 S0.4：读冲突记录，逐条按三道门判断——
   - 门一：主题标签完全相同；
   - 门二：新卡生效日期严格晚于旧卡（同日期不许用）；
   - 门三：相似度 ≥ 0.85。
   三条件全过 → 旧卡置"已作废"并写 superseded_by；任一不过 → 两张都置"有争议"，留给阶段 2 的人工通道。
3. 报告增加一节：本轮自动作废几条、转人工几条、各自的判断依据（便于回溯）。

**验收**

- 用现有 3 条冲突做第一批实测：先 `--dry-run --no-llm` 打印计划，人工核对每条是否符合三道门。
- 真跑后：旧卡状态=已作废、正文 sha256 不变、同一主题在检索里只剩一张卡、注入块里该主题的冲突行消失。
- 反向用例：相似度 0.9 但主题不同的两条（如端口 8080 / 8081）必须被拒，走"有争议"。

**回滚**：dream 每轮报告含前后对照；旧卡正文从不改，只有 header 状态字段变，可逐条改回。

## 6. 阶段 4 · 遗忘可解释 <a id="阶段-4"></a>

**现状**：权重 w=min(1,max(下限,2^(-龄/30)))，见 lib/decay.js:15-19；冷热分层另看连续未中次数（tier.js:122-123）；但用户看不到"为什么被降权"。

**改动点**：阶段 1 的事实卡视图里每条加一行「权重 0.62（龄 14.3 天，半衰 30 天，下限 0.35，连续未中 3 次）」。纯展示，不改打分。

**验收**：任取一张卡，手算 2^(-14.3/30)=0.717 与界面一致；改动前后同一轮注入块 md5 相同。

**回滚**：纯展示层改动，回退该行即恢复原视图，打分与检索均不受影响。

## 7. 阶段 5 · 主题归并（标签前缀，零模型） <a id="阶段-5"></a>

**目标**：同一主题积累多张卡后不靠模型聚类，用标签前缀机械归并成一张"主题索引卡"。

**做法**：按 `decision.` / `env.` / `pref.` / `lesson.` 前缀分组，每组生成一张索引卡（只列"子主题 + 一句话结论 + 卡 id"，不复制正文），原卡保留但降权不再单列。

**验收**：归并后检索同一主题只命中索引卡 + 最多一张明细卡；题库命中率不下降。

**回滚**：索引卡是独立文档，删除即回退。

## 8. 阶段 6 · 写入门控（条件触发，暂不排期） <a id="阶段-6"></a>

**前提**：阶段 0 题库 + 阶段 3 裁决数据齐备，能算出"筛掉的都是噪声、留下的都是真货"。

**做法**：20 条已入库卡离线回放，规则打分（用户显式强调加权、与空白主题相关加权、同主题无新证据减权），precision ≥ 0.8 才允许接入蒸馏脚本前置过滤，且带 `--gate` 开关默认关。

**验收**：离线回放 20 条已入库卡，规则打分的 precision ≥ 0.8；`--gate` 默认关时不改变现有写入行为。

**回滚**：`--gate` 默认关，不打开即等同现状，现有写入链路不受影响。

## 9. 夜间调度调整（已定，尚未执行）

**决定（用户 2026-11-05）**：蒸馏脚本 00:00，裁决脚本 00:30；每小时导入不动；每周任务不动。

**为什么不是简单平移**：裁决脚本裁决的是"知识库里已存在的卡"，蒸馏脚本才是产卡方，现在的顺序让当夜新卡慢一拍。

下例中的 `<workspace>` 请替换为实际工作区目录后再执行。

```powershell
# 备份现状
schtasks /query /tn DSH-Session-Distill /xml ONE | Set-Content <workspace>\_wk_spec\task-Distill-before.xml -Encoding UTF8
schtasks /query /tn DSH-Memory-Dream  /xml ONE | Set-Content <workspace>\_wk_spec\task-Dream-before.xml  -Encoding UTF8

Set-ScheduledTask -TaskName 'DSH-Session-Distill' -Trigger (New-ScheduledTaskTrigger -Daily -At '00:00')
Set-ScheduledTask -TaskName 'DSH-Memory-Dream'    -Trigger (New-ScheduledTaskTrigger -Daily -At '00:30')
Get-ScheduledTaskInfo -TaskName 'DSH-Session-Distill','DSH-Memory-Dream' | Select TaskName,NextRunTime
```

回滚：把 `-At` 换回 `04:30`（蒸馏）与 `03:30`（裁决）重跑一次；或直接 `Import-ScheduledTask` 那两个备份 xml（`<workspace>\_wk_spec\task-Distill-before.xml` 1748B、`task-Dream-before.xml` 1521B）。

同步改注册脚本防回退：`<workspace>\_wk_distill\create-task.ps1:5`、`writers\register-tasks.ps1:20`（及 :13 注释）。

风险：与每小时导入的 :52 轮次是否重叠**待核实**（需先取 3 轮导入日志的时间差）。常驻记忆里的旧值已于 2026-11-05 01:21 改为「每日 00:00 自动蒸馏条目、00:30 夜间裁决」（`wk-inject.config.json` 的 `pinned[1].text`）。
